مطعم وكافيه أوتار — حساب مدير وموظف للسحب والتسديد

حالة النسخة: ملفات جاهزة للربط؛ لا توجد قاعدة بيانات مفعّلة ضمن الملف.
لا تعمل الحسابات المشتركة قبل إكمال خطوات التفعيل أدناه.
تم فحص صياغة JavaScript. لم يتم اختبار اتصال حي أو تنفيذ SQL على مشروع فعلي.

التفعيل مرة واحدة:
1. أنشئ مشروعاً في https://supabase.com واحفظ كلمة مرور قاعدة البيانات لديك.
2. افتح SQL Editor وشغّل محتوى database.sql مرة واحدة على مشروع جديد.
3. من Authentication > Users > Add user أنشئ حساب المدير ببريدك وكلمة مرور قوية، واجعله مؤكداً. انسخ User UID.
4. في SQL Editor نفّذ بعد وضع UID الحقيقي:
insert into public.awtar_users(user_id,role,name) values('OWNER_UUID','admin','عمر');
5. ارفع index.html وsecure.js معاً في نفس مجلد موقع GitHub Pages القديم. لا يلزم رفع database.sql.
6. من إعدادات المشروع انسخ Project URL والمفتاح العام publishable أو anon.
7. افتح البرنامج > إعداد الربط أول مرة وأدخل الرابط والمفتاح العام. لا تستخدم service_role أو sb_secret.
8. سجّل دخول المدير. افتح المواد والمستخدمون والسجل. استورد بيانات الجهاز القديمة من نفس المتصفح ونفس رابط الموقع السابق، أو استورد نسخة JSON من النسخ الاحتياطي.
   الاستيراد متاح فقط عندما تكون القاعدة المشتركة فارغة؛ يحتفظ البرنامج بالبيانات المحلية القديمة ولا يمسحها.
9. أضف المواد وأسعارها الثابتة. لإيقاف مادة استخدم إيقاف. لإضافة سعر جديد أوقف المادة القديمة وأضفها بالسعر الجديد؛ الحركات السابقة تحتفظ بسعرها.
10. أنشئ حساب الموظف من Authentication > Users، ثم أدخل UID واسمه في إدارة المستخدمين داخل البرنامج. أرسل له رابط البرنامج وبيانات دخوله بنفسك. أدخل نفس إعداد الربط في جهازه.

الصلاحيات:
- المدير: وظائف النسخة السابقة، إدارة المواد، إضافة الموظفين وإيقافهم، سجل الرقابة.
- الموظف: يرى أسماء حسابات الديون وأرصدتها لاختيار الحساب. يسجل سحب مادة بسعر ثابت وكمية صحيحة أو تسديداً لا يتجاوز المتبقي.
- الموظف لا يضيف حسابات أو مواد، لا يغيّر أسعاراً أو تواريخ أو أسماء، ولا يقرأ الإيرادات والمصروفات والمجهزين والسلف. لا يعدّل أو يحذف أي حركة.
- الموظف لا يحصل على حساب إدارة Supabase أو GitHub ولا كلمة مرور المدير.
- قاعدة البيانات تتحقق من الصلاحية في كل طلب، وتحسب سعر السحب ورصيد التسديد داخل معاملة مقفلة لمنع تعارض العمليات.
- سجل الرقابة منفصل ولا يسمح التطبيق بتعديله أو حذفه. عمليات الموظفين تحفظ الاسم والتاريخ والوقت حسب بغداد.
- بيانات المدير تُحفظ برقم إصدار: عند تعارض تغييرين يرفض الحفظ ويطلب إعادة إدخال التغيير بعد تحديث البيانات.
- التحديث بين الأجهزة بزر تحديث؛ لا توجد مزامنة لحظية في الخلفية.
- الحفظ يحتاج اتصال إنترنت؛ لا يوجد حفظ مالي دون اتصال.
- إذا انقطع الاتصال أثناء التسجيل، حدّث الرصيد وتحقق قبل إعادة العملية.
- حركات قديمة بلا اسم موظف تبقى كما هي. الأسعار الجديدة لا تغيّر الديون السابقة.
- السحب يضاف كدين على الحساب؛ هذه النسخة لا تدير كميات المخزون الفعلية أو سندات شراء المخزون.
- احتفظ بنسخة JSON دورياً. لم يُنقل أي سجل شخصي إلى خدمة خارجية بواسطة هذا التعديل.
